# Аудит форм заявки

## Инвентарь форм

1. **`form.appeal`** на index.html (секция «Контакт») и contacts.html — поля: `name` (required), `contact` (телефон или email, required), `message` (textarea, опционально), `website` (honeypot, скрыт).
2. **Формы виджета** (`renderForm`/`renderCallback` в widget.js) — в текущем меню виджета **недостижимы** (пункты «Написать сообщение»/«Обратный звонок» не выводятся) — мёртвый код, зафиксировано в 15_BUGS_REMAINING.md. Активные пункты виджета: WhatsApp / Telegram / Позвонить.

## Логика отправки (main.js)

- Если задан `CONTACTS.formEndpoint` → `POST JSON {name, contact, email?, message?, page}`; успех — только при HTTP ok **и** `{ok:true}` в ответе.
- Если endpoint пуст (текущее состояние) → открывается WhatsApp с автозаполненным текстом заявки. **WARNING: Worker не подключён** — см. 04_TELEGRAM_WORKER_AUDIT.md.

## Тесты (e2e, mock-endpoint — реальные заявки не отправлялись)

| Сценарий | Результат |
|---|---|
| Пустая форма → отправки нет, браузерная валидация (reportValidity) | PASS |
| Имя+контакт заполнены → loading («Отправляем…», кнопка disabled) → панель «Заявка отправлена» → форма скрыта | PASS |
| «Отправить ещё одну» → форма возвращается очищенной | PASS |
| Double-submit: 5 быстрых кликов → **ровно 1 запрос** (disabled-кнопка) | PASS |
| Ответ сервера 502/`{ok:false}` → понятное сообщение «Не удалось отправить заявку. Попробуйте ещё раз.», без Failed to fetch/кодов, форма сохраняет введённое | PASS |
| Сеть недоступна (abort) → то же понятное сообщение | PASS |
| Honeypot `website` заполнен → запрос не уходит | PASS |
| Имена: «Худоёр», "O'Connor-Smith", "Anna Maria" (кириллица/латиница/пробел/дефис/апостроф) → принимаются без искажений | PASS |
| Повторная отправка: клиентский rate-limit 1 раз/20 сек (общий с виджетом, сбрасывается при ошибке) | PASS (код-ревью + тест двойной отправки) |

## Валидация полей

- Поле `contact` принимает и телефон, и email — жёсткой маски нет (осознанно: международные форматы не блокируются). Форматы `+992 900 00 00 00`, `900000000`, `+7…`, `test@example.com` — принимаются; мусор вида «test» тоже пройдёт клиентскую проверку (только required). Это компромисс UX; сервер дополнительно обрезает длину. Ужесточение не вносилось, чтобы не отсекать реальные контакты.
- Длинные значения: клиент не ограничивает, **Worker обрезает** (имя/контакт 100, message 1500, payload ≤64KB) — unit-тест PASS.
- Ошибка выводится в `role="alert"` контейнере — скринридеры озвучивают. PASS.

## Label/доступность

- У всех видимых полей есть `<label>` (не placeholder-only). Замечание: label не связаны с input через for/id (идут непосредственно перед полем). Функционально читается скринридерами по порядку; рекомендация на будущее — добавить for/id (P3, не блокирует). Honeypot скрыт `aria-hidden` + tabindex=-1 — PASS.
