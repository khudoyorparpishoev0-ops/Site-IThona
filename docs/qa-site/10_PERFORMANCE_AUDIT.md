# Performance-аудит

## Lighthouse

**NOT TESTED** — Lighthouse недоступен в аудит-окружении (нет внешней сети для честного прогона; локальный прогон без шрифтов/карт дал бы искажённые числа, подгонять score запрещено правилами аудита). Ниже — фактические изменения состава страницы, которые напрямую влияют на метрики, и ожидания по ним. Запустить Lighthouse на проде — пункт релиз-чек-листа.

## Сделанные оптимизации

| Что | Было | Стало | Эффект |
|---|---|---|---|
| `company-new.png` (hero-фото services/contacts + фото на index) | **2 289 KB** PNG | **235 KB** JPEG (q82, progressive) | LCP на services/contacts: −2 МБ критического веса; самая крупная победа |
| Шрифт Inter | Грузился дважды: `<link>` в HTML + `@import` в style.css | Только `<link>` | −1 блокирующий CSS-запрос на каждой странице |
| Изображения ниже первого экрана (company-home на index/about/services, фото услуг на index) | eager | `loading="lazy" decoding="async"` | Меньше работы на старте; брендовые логотипы уже были lazy |
| CLS | `img` без размеров | `width/height` у контентных фото, у hero — размеры + контейнеры с фиксированной высотой (CSS) | Стабильная раскладка; hero не лazy (правильно), десктопному hero добавлен `fetchpriority="high"` |
| Версионирование кэша | — | `?v=` подняты у всех изменённых ассетов | Пользователи получат новые файлы сразу |

## Текущий вес (первая загрузка, до кэша)

- HTML: 12–21 KB/страница.
- CSS: style.css ~19 KB + editorial.css ~15 KB (не минифицированы — для такого объёма выигрыш минификации ~10 KB; сознательно без build-pipeline, зафиксировано как опция).
- JS: main+i18n+widget+cookie ≈ 46 KB суммарно, без фреймворков — отлично для статического сайта.
- Изображения: hero-desktop 165 KB, hero-mobile 183 KB, hero 263 KB, company-home 327 KB (lazy), company-new 235 KB, логотипы 12 шт ≈ 252 KB (lazy), og-image 57 KB (не грузится на страницу).
- Внешнее: Google Fonts (6 начертаний — реально используются 400–900), Яндекс-карта только на index/contacts (iframe lazy).

## Ожидания по метрикам (обоснование, не измерение)

- LCP: hero-изображения 165–263 KB + fetchpriority — на 4G ожидаемо <2.5s; на services/contacts после замены PNG→JPEG улучшение кратное.
- CLS: ~0 (фиксированные контейнеры + width/height).
- TBT: минимальный — JS лёгкий, без long tasks (счётчики на rAF).

## Рекомендации (не внедрялись — вне безопасного минимума)

1. WebP/AVIF-версии фото через `<picture>` (ещё −30–50% веса фото).
2. Self-host шрифта Inter (2 woff2 вместо 6 начертаний с Google CDN) — быстрее и приватнее.
3. Убрать неиспользуемые блоки style.css (старый дизайн: .hero, .stats-panel, .project, .solution, .quick и др. — на v2-страницах не применяются; ~40% файла) — требует аккуратной сверки, риск против выгоды ~8 KB.
4. Cache-Control на хостинге: HTML — `no-cache` или короткий max-age; картинки — длинный max-age; CSS/JS — длинный только при `?v=`-версионировании (используется). `immutable` без хэшей в именах — осторожно.
5. `about-company.jpg` (330 KB) не используется ни одной страницей — можно удалить из деплоя.

## Отказоустойчивость

- Без JS сайт читается: контент, контакты, навигация видимы (e2e с javaScriptEnabled:false) — PASS; форма/i18n без JS не работают (допустимо).
- Падение widget.js/cookie.js не ломает сайт и навигацию (e2e с подменой скрипта на 404) — PASS: модули в самостоятельных IIFE; единственная связка — inline-скрипт языка зовёт applyLang из i18n.js, при недоступности i18n.js остальные модули уже инициализированы (порядок: main → i18n → widget → cookie; ошибка последнего inline-блока не влияет на них).
- Глобальные коллизии: window.CONTACTS/I18N пробрасываются явно; остальное в IIFE; конфликтов имён нет (проверено) — PASS.
- Критической зависимости от сторонних ресурсов нет: при недоступности Google Fonts текст рендерится системным шрифтом; карта — просто пустой iframe (страница работает — фактически проверено всеми e2e-прогонами с заблокированной внешней сетью).
